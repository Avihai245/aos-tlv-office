# QA report, 2026-10-29

Results of the site audit (responsiveness, speed, flows, RLS, security, double booking). Code fixes landed in PRs #1 to #4; this file records how each item was checked.

| # | Check | Result | How it was verified |
|---|---|---|---|
| 1 | Fully responsive | Pass | DOM audit at 320/360/390/430 px, tablet and desktop: no horizontal scroll, no clipped elements. |
| 2 | Fast on mobile | Pass | Lighthouse mobile: performance 93-95 (was 72), LCP ~3s on simulated slow 4G (was 8.5s), SEO 100. Hero video 8.4 MB to 1.2 MB. |
| 3 | All flows and buttons work | Pass | Every page, form, booking flow, landing page, sign-in and membership flow walked through. |
| 4 | RLS and user isolation | Pass | RLS on every table; `anon` gets 42501 on bookings, profiles, payments, inquiries, memberships, audit_log. Users can update only name/phone/company on their profile. Every admin RPC checks `private.is_admin()`. |
| 5 | Security gaps closed | Pass | Customers cannot confirm their own booking; abuse caps on `create_hold`, `request_booking`, `add_inquiry` (PR #4). Leaked-password protection enabled in Auth > Attack Protection and confirmed gone from the Supabase security advisor. Remaining advisor warnings are intended `SECURITY DEFINER` RPCs that check the caller themselves. |
| 6 | No double booking (site and landing pages) | Pass | Exclusion constraint `bookings_no_overlap` on room + time range. Two-browser race: two temporary users in two browsers (built-in pane and Chrome) called `create_hold` for the same slot in the same millisecond; one got the hold, the other got `taken`, and the database held exactly one booking. Landing pages use the same RPC. Test users and booking deleted afterwards (counts 0). |
